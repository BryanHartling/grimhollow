# Grimhollow updates

The home-screen updater reads public GitHub Releases for `bryanhartling/grimhollow`. It never authenticates and contains no GitHub token. Normal pushes still run the existing acceptance workflow; version tags publish only after both desktop jobs, Android and all four smoke jobs pass. Failed or incomplete releases remain unpublished. Release assets are uploaded to a draft before it becomes visible.

Each release contains a complete Windows x64 ZIP, Android APK, exact-byte RSA/SHA-256-signed manifest, detached signature, checksums and notes. The public key is shipped in `core/src/main/assets/updates/public-key.der`. The private key lives in the ignored `.local/update-signing/` directory and the Actions secret `GRIMHOLLOW_UPDATE_PRIVATE_KEY_B64`; never commit it. Metadata binds the repository, tag, channel, monotonically increasing build number, filenames, HTTPS URLs, sizes and hashes. Runtime rejects altered manifests, foreign URLs, downgrades, oversized downloads and mismatched files. Update prompts happen on the home screen; installation never interrupts combat.

Android's delivery build preserves the signing certificate of this machine's existing APKs. `tools/updates/env.ps1` loads its local DPAPI-protected password for `android:assembleUpdate`. CI requires `GRIMHOLLOW_ANDROID_KEYSTORE_B64`, `GRIMHOLLOW_ANDROID_STORE_PASSWORD` and `GRIMHOLLOW_ANDROID_KEY_PASSWORD`. Signed delivery APKs are separate from the ephemeral debug artifacts. An APK installed previously from a CI debug artifact can have a different certificate; runtime refuses that incompatible update rather than uninstalling it or deleting saves. Such devices require a separately planned migration. Android's own installer controls final consent and may require allowing installations from Grimhollow.

To provision Actions secrets, use `provision.py` with PyNaCl available and `GRIMHOLLOW_TOKEN` set only in the process environment. The fine-grained token needs repository Secrets read/write. Pass the ignored local signing directory. The script uses GitHub's public key to encrypt the values and logs only secret names. A missing secret fails a tagged release closed; branch checks can still build their normal debug artifacts.

Windows installation is limited to a complete, writable packaged application, not development jars. An external helper validates the archive again, extracts within a checked sibling directory, waits for the old process to exit, keeps the previous application, and rolls back if the new launch never confirms a healthy home screen. Saves and preferences live separately and are backed up before installation; code rollback does not silently overwrite newer save data. Interrupted downloads never become installable. Network errors leave the current game usable.

The historical network audit now permits only the guarded update transport; legacy SPD update/news clients stay disabled. Native smoke/review launchers disable all updater traffic. No art, gameplay, generation or balance changes belong to this component.
